# Информационная система склада на C++

Консольная программа для лабораторной работы. Учитывает поступление товара,
размещение по местам хранения, сборку заказов, инвентаризацию со списанием,
отгрузку и уведомления. Классы и сценарии соответствуют диаграмме классов и
диаграммам последовательностей из корня репозитория.

## Компиляция и запуск

```bash
g++ -std=c++17 -Wall -Wextra -pedantic \
    main.cpp storage.cpp warehouse_entities.cpp warehouse_system.cpp \
    -o warehouse_demo
./warehouse_demo
```

На Windows (MinGW) команда та же, запуск — `warehouse_demo.exe`. Кодировка консоли
переключается на UTF-8 автоматически в `main.cpp`.

## Меню

```text
==================================================
        ИНФОРМАЦИОННАЯ СИСТЕМА СКЛАДА
 Центральный склад, г. Москва, ул. Складская, 1
==================================================
 Ячейки: занято 1.80 из 12.00 м³ (резерв 0.00 м³), партий: 2
 Зона приёмки: 0 парт. | Зона отгрузки: 0 парт.
 Поставок ожидается: 0 | заказов: 0 | новых уведомлений: 0
--------------------------------------------------
 1. Показать структуру склада
 2. Подготовка и приёмка товара
 3. Размещение товара
 4. Создание и комплектация заказа
 5. Инвентаризация
 6. Отгрузка товара
 7. Показать уведомления
 8. Выход
--------------------------------------------------
```

- Пользователь вводит номер пункта и нажимает Enter.
- Вверху — строка состояния склада, рядом с пунктами — подсказки
  («ожидается поставок: 1», «ждут размещения: 1», «готово заказов: 1»…).
- Ошибка ввода показывается прямо под меню.
- В сценариях **Enter без числа подставляет значение по умолчанию**, поэтому
  основной сценарий можно пройти одними Enter.
- Каждый сценарий выводит: цепочку вызовов классов → работу методов → итог.

На складе сразу есть товар (молоко и сахар), поэтому любой пункт можно показать
без подготовки.

## Сценарии

Порядок для демонстрации: 2 → 1 (регистрация) → 2 → 2 (приёмка) → 3 → 4 → 5 → 6 → 7.

| Пункт | Метод `WarehouseSystem` | Что происходит |
|---|---|---|
| 1 | `showWarehouseStructure` | Дерево склада: шкафы → полки → ячейки → партии, буферные зоны, свободный объём |
| 2.1 | `registerDelivery` | Оператор создаёт накладную (1–3 позиции, срок поставки). Для каждой позиции ищется свободная ячейка и резервируется место. Если места нет — уведомление оператору |
| 2.2 | `receiveDelivery` | Кладовщик вводит фактическое количество. При расхождении оператор выбирает: принять с расхождением или отклонить позицию. Партии создаются по факту, резерв снимается, партии ждут размещения в зоне приёмки |
| 2.3 | `checkDeliveryDates` | Проверка сроков ожидаемых поставок: «ожидается сегодня», «срок истёк» |
| 3 | `placeGoods` | Склад находит свободную ячейку (`findFreeCell` через шкаф и полку), партия переносится из зоны приёмки в ячейку |
| 4 | `createOrder`, `pickOrder` | Заказ из 1–3 позиций. Склад определяет, где лежит товар, и отбирает его из партий. Если товара мало — заказ остаётся «комплектуется», его можно дособрать позже в этом же пункте |
| 5 | `startStocktake` | Пересчёт всех партий в ячейках. Недостача списывается, излишек оприходуется. `-1` — ячейку проверить не удалось: сессия не завершается |
| 6 | `createShipment` | Сначала проверяется комплектность заказа. Собранный товар переносится в зону отгрузки, проверяется соответствие заказу, оператор подтверждает отгрузку, заказ получает статус «отгружен» |
| 7 | `showNotifications` | Список уведомлений, новые отмечены `*` |

## Связи классов

```text
Warehouse
 ├── StorageCabinet          (композиция)
 │    └── Shelf              (композиция)
 │         └── StorageCell   (композиция)
 └── BufferZone              (агрегация: зонами владеет WarehouseSystem)

StorageLocation (абстрактный: id, capacity, currentVolume, batches)
 ├── StorageCell
 └── BufferZone
```

`Warehouse`, `StorageCabinet` и `Shelf` не наследуются от `StorageLocation`.
Занятый объём места хранения (`getCurrentVolume`) считается как сумма объёмов партий,
поэтому он всегда совпадает с реальным содержимым.

`GoodsBatch` (партия) хранит товар, количество, объём, резерв, статус и текущее место
хранения. Статусы партии: принята, размещена, зарезервирована, израсходована.

Предметные классы:

- `Product` — товар;
- `DeliveryNote`, `DeliveryNoteItem`, `Delivery` — приёмка поставки;
- `WarehouseOrder`, `OrderItem` — заказ и его позиции;
- `StocktakeSession`, `StocktakeItem` — инвентаризация;
- `Shipment`, `ShipmentItem` — отгрузка;
- `Notification` — уведомление. Уведомления о приёмке, расхождениях при
  инвентаризации и отгрузке создают `DeliveryNote`, `StocktakeItem` и `ShipmentItem`.

## Файлы

- `storage.h/.cpp` — склад, шкафы, полки, ячейки, буферные зоны, партии;
- `warehouse_entities.h/.cpp` — товар, приёмка, заказы, инвентаризация, отгрузка, уведомления;
- `warehouse_system.h/.cpp` — меню и сценарии;
- `main.cpp` — запуск.

Все основные методы печатают сообщение вида `Класс::метод: что сделано`, чтобы на
защите была видна цепочка вызовов. Геттеры (`getAddress`, `getCapacity` и т. п.)
ничего не печатают — они используются для строки состояния в меню.
